# Windows 键色透明窗口踩坑实录：tkinter `-transparentcolor` 方案的全部代价

> 本文来自一个 Python 桌面宠物项目的真实开发记录（2026-06 ~ 2026-09）。
> 项目先用 tkinter 键色方案做了几个月，最后整体迁移到 PySide6 逐像素
> 透明窗口，并在 AGENTS.md 里记下结论：**键色窗口是万恶之源**。
> 这篇是它"恶"在哪的完整清单，配套的 Qt 侧实录见姊妹篇
> 《PySide6 逐像素透明窗口踩坑实录》。

## 方案回顾

Windows 上 tkinter 没有逐像素 alpha，透明只有一个办法：
`-transparentcolor`——指定一种颜色，窗口上**恰好等于该色的像素**
在合成时完全透明：

```python
root.config(bg='#010101')
root.wm_attributes('-transparentcolor', '#010101')
```

宠物画在 Canvas 上，背景填键色（`#010101`，近黑但不与精灵配色冲突），
看起来就是"透明窗口"。半透明气泡用 Canvas stipple 实现：`gray75`
内建 stipple 或自定义 XBM 位图（8x8 每行 1 个透点 = 87.5% 镂空），
镂空点露出键色背景 = 桌面，等效 75%/87.5% 不透明，不需要分层窗口。

## 代价一：整条资产链都在伺服键色窗口

键色窗口**只认二值 alpha**：一个像素要么等于键色（透明），要么不是
（不透明）。所有边缘细节都在这里丢失，并反向污染了整条素材生产链：

1. **精灵帧 alpha 必须二值化**。rembg 抠图输出的是软 matte——几乎没有
   alpha=255 的像素——半透明像素会先与近黑键色混合再上屏，产生暗边。
   所以每帧都要 `alpha >= 128 → 255 else 0`。
2. **边缘渗色**。抠图外围像素的 RGB 混着背景色，缩放插值后形成背景色
   晕/黑边。必须把边缘环带的颜色用核心区颜色外扩填充。
3. **蒙版腐蚀**。源图边缘"人物与底色反锯齿混合像素"整体保留成描边，
   需要在源分辨率上把 alpha 蒙版向内腐蚀 1~3px（实测白边像素 89% → 4%）。
4. **绿幕键控的空腔判罚**。纯色底抠图用四角取色 + 块级洪泛，两腿之间、
   臂弯里被人物围住的底色洪泛到不了，需要"封闭近背景色空腔"判罚
   （阈值要标定：真底色空腔色距 ~0-11，人物内部浅肤/阴影空腔 ~19-27，
   判错会破大腿/胸口）。
5. **透明像素 RGB 必须清零**。键色窗口拿透明像素的 RGB 与键色混合，
   残留颜色就是暗边——这成了图集契约的硬性校验项。

一条本来可以只做"抠图"的管线，多出二值化、渗色、腐蚀、空腔判罚、
RGB 清零五道工序，全部为了伺服一个键色合成器。

## 代价二：tkinter 运行时的坑

**PhotoImage 不能运行时翻转/旋转**。所有镜像与姿势变换必须在构建期
烘焙进资产（每状态 [朝右×N, 朝左×N] 两套帧）。

**PhotoImage 缓存必须挂在 canvas 组件上**。PhotoImage 属于创建它的
Tk 解释器，模块级缓存跨 Tk 实例（多实例/测试每用例新建 `tk.Tk()`）
会复用已销毁实例的死图，`copy -from` 报 `TclError: image doesn't exist`，
`_tick` 崩掉 after 链、动画冻结——且异常只打 stderr，极易漏看。

**tk_popup 菜单打开期间 after 定时器照常触发**。`menu.tk_popup` 会
阻塞直到菜单关闭，但主循环定时器还在跑；每帧的 `SetWindowPos` 置顶
压制会把刚弹出的菜单挤掉。必须用 `_menu_open` 标志跳过窗口移动/置顶。

**菜单锚定高度只能估**。Windows 菜单项实测 ~22px/项，按 26px/项估算
（宁大勿小——估小了菜单会沉到宠物后面被键色窗口盖住）。

**落地高度必须按工作区自适应**。窗口 = 对话区 + 宠物区，脚底在窗口
底边，地面要取 `GetMonitorInfoW` 的 rcWork（`EnumDisplayMonitors` 只给
整屏矩形），按 `工作区底边 - (size + 对话区高)` 落位。按"窗口顶 =
整屏底 - size"写死的话，125% DPI 下整只宠物沉到屏幕外约一个对话区高。

## 代价三：性能与画质的天花板

主循环是 30ms after tick，每 tick 无条件 `delete('all')`×2 + geometry
调整 + `SetWindowPos` 置顶压制——键色窗口每秒整帧重合成 30 次，帧边界
与定时器 tick 不对齐就跳帧/重复帧，表现为人形轮廓"闪"。

画质上限则由代价一决定：软 alpha、阴影、光效、半透明全部被砍。
结论写在项目交接文档里：**键色窗口是万恶之源**。

## 迁移判断

什么时候该放弃键色方案：

- 精灵想要软边缘、阴影、光效、真半透明——任何非二值 alpha；
- 帧率或流畅度到了瓶颈（整帧重合成的开销躲不掉）；
- 资产链工序多到开始出现"为键色而做"的专项标定。

2026-09 迁移到 PySide6 `WA_TranslucentBackground` + `setMask` 后，
上面代价一的五道工序全部退役（保留软 alpha 即可），tk 层降级为
"零依赖兜底"冻结。迁移侧的坑（QBitmap access violation、QRegion
绑定缺失、双重镜像等）见姊妹篇。
